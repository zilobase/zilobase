# Agent execution and MCP

[Agent modules](../../../apps/server/src/features/ai/agents) own profiles/revisions, resources and triggers. [Conversations](../../../apps/server/src/features/ai/conversations) own conversation state; [execution](../../../apps/server/src/features/ai/execution) owns durable run orchestration, records, leases and checkpoints. [Jobs](../../../apps/server/src/features/ai/jobs) implement queued AI work. [Background composition](../../../apps/server/src/app/background/processor.ts) dispatches agent.run and ai.job tasks to those implementations.

[MCP modules](../../../apps/server/src/features/ai/mcp) own connector access, OAuth, tool discovery, tool snapshots, approval and execution. The model's requested tool is not itself authorization: actor scope, connection access and tool execution mode constrain what can run. [Pinned Node transport](../../../packages/runtime-adapter/src/node/pinned-mcp.ts) is the concrete secure outbound mechanism; the [runtime capabilities](../../../packages/runtime-adapter/src/capabilities.ts) reject MCP requests when the required transport is absent.

[Tool implementations](../../../apps/server/src/features/ai/tools) apply page/database operations and [file routes](../../../apps/server/src/features/ai/files/routes.ts) handle AI file interactions. Resource permissions and persisted run state remain server-owned. Web conversation state renders streaming output and approvals; it must not duplicate the server's execution policy.

When changing this flow, cover permission denial, approval requirements, cancellation, connector revocation and durable run recovery. Preserve existing tool names and shared contracts. Tests beside agent/MCP modules are the implementation-level starting point; the [operations guide](../../../docs/ai/ask-ai-operations.md) describes runtime diagnosis.

## Durable run interface and implementation

[Run operations](../../../apps/server/src/features/ai/execution/agent-run-service.ts) remain the entrypoint for listing, details, cancellation, queue draining, approval expiry and `processAgentRun`. Processing claims the persisted run, starts its renewable lease and delegates to [model continuation](../../../apps/server/src/features/ai/execution/agent-run-model.ts). Continuation restores the encrypted checkpoint, rejects uncheckpointed writes on retries, prepares context, persists before model execution and saves each completed step. A null result means the initial checkpoint suspended execution for approval; a final result returns to orchestration for the existing live-status and lease-owner checks. Claiming, terminal/retry updates, conversation status and dispatch stay in run operations; the lease always stops in its `finally` block.

[Run context](../../../apps/server/src/features/ai/execution/agent-run-context.ts) loads the pinned revision and active profile, checks current resource-editor eligibility, resolves the model and composes native/MCP tools. Malformed native permission snapshots become no grants. Native tools require both captured grants and current access; MCP retains its own snapshot validation and approval policy. [Native tool implementations](../../../apps/server/src/features/ai/tools/agent-native-run-tools.ts) own resource operations, durable receipts and uncertain-write errors. The [connection tool](../../../apps/server/src/features/ai/tools/agent-connection-tool.ts) writes the existing scoped Connect-card message with the initiating user or profile owner as author. These implementations do not claim or complete runs.

Interactive [chat composition](../../../apps/server/src/features/ai/conversations/chat-service.ts) continues to select registered workspace, MCP and personal-settings tools through their existing builders. Its request-scoped database adapter, streaming lifetime and actor policy remain separate from durable runs. Provider/MCP adapters are already concrete variations; no additional generic tool dispatcher is needed.

The [continuation tests](../../../apps/server/src/features/ai/execution/agent-run-continuation.test.ts) exercise the public processing interface with controlled model, persistence and connector dependencies: write-replay prevention, checkpointed completion, approval suspension, cancellation, retries, missing revisions, revoked editors, snapshot filtering, initial-checkpoint failure and Connect-card authorship. They replace the former source-string permission assertions. [Lease tests](../../../apps/server/src/features/ai/execution/agent-run-lease.test.ts) and [checkpoint tests](../../../apps/server/src/features/ai/execution/agent-run-checkpoint.test.ts) cover the respective mechanisms. These tests do not establish real PostgreSQL worker contention or live provider behavior.
